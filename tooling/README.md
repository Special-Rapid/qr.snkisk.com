# Asset generation and preparation sources

<a id="画像生成と資産準備の編集元"></a>

Edit the three TypeScript modules in `src/`. The root `npm run build:tooling` performs strict type checking and then generates matching MJS files and declarations derived from the actual sources in this folder. Type errors prevent emit. The existing TypeScript compiler comes from the extension's locked dependency. Do not edit generated MJS or declarations directly. CI's `npm run check:tooling` compares the complete outputs generated in an empty temporary directory with the public output set, bytes, manifest, and Git tracking/diff state. It also rejects orphaned outputs from additions, renames, or deletions, and untracked or ignored generated files.

Root asset generation, brand/native preparation, and asset checks build first. Existing native, CLI, and standalone calls use the same distributed MJS inputs rather than executing MTS sources directly. Outputs are tracked so native environments and standalone environments with only pngjs available can retain the existing JavaScript inputs.

The canonical icon source is `assets/brand/qr-scan-icon.svg`. `generate-brand-assets` produces the existing nine SVG/PNG/Android-vector derivatives. `--check` compares SVG/vector bytes and PNG dimensions and every pixel. Sources, sizes, alpha, distribution paths, and appearance are unchanged. Do not edit derived images directly.

`prepare-native-assets` uses the existing lock's URL/size/MIME/hash/path checks and an external cache. It validates every input before touching bundle inputs, then renames each path from a temporary file. Existing behavior on failure, including steps not reached, preserved inputs, and the next rerun, is retained; this adds neither ACID for the whole bundle nor rollback for partial I/O failures. Leaf type projections for unknown locks and exceptions describe existing access, without new validation or schema guarantees.

The existing asset tests `test/native-assets.test.mts` and `test/standalone-generator.test.mts` also undergo strict/noEmit type checking. The root `npm run test:build-assets` generates helpers and type-checks tests before running the existing 18 cases. `tsconfig.test.json` is test-only, typing fixture TestContext, arguments, and fake fetch. Existing assertions, accepted/rejected inputs, and side effects are preserved; fixture annotations are not runtime validation. CDN uploads, actual native builds, devices, signing keys, and production operations are outside this type-migration scope.

`build-tooling.mts` also undergoes strict type checking. Run it with Node.js 22.18 or later; it uses the root/extension's existing locked TypeScript. The three modules generate into an empty temporary directory. Only after type checking and reading all outputs does the builder update paths owned by `generated-files.json`. MJS and declarations are flat, same-name pairs. Existing candidates outside the manifest and symlinks are untouched. Type errors preserve existing outputs, and old owned outputs left after source removal are deleted only after successful generation. Before applying output, the manifest records the union of old and new ownership; after each path is renamed, the final expected set is saved last. Partial outputs during source additions or renames can also be regenerated from the same source using recorded ownership. This assumes a fixed checkout and one builder, claims no ACID for the entire set, and detects partial failures through checks so the same source can be rerun.
